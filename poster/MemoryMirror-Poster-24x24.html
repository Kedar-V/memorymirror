MemoryMirror

See, trace, and correct the memories an assistant is using.

Figure 1 · Memory as a mirror: beliefs become inspectable reflections of prior talk
Motivation

Assistants now keep durable “memories” about people. When those memories are wrong, stale, or over-inferred, the person usually cannot see the record, cannot prove where it came from, and cannot test whether fixing it changes the next reply.

Research question
When an assistant answers from a stored memory, can a person see that memory, trace it to a source message, correct it, and get a different answer to the same question under the same model and the same agent settings?
Domain: Human–AI interaction · Explainable AI · Memory provenance
Audience: People subject to assistant memory, and builders who need a correction loop they can evaluate
Contribution

Method

Hold the model fixed. Change only memory.

Three synthetic people ship with a planted stale or over-inferred belief. The lab freezes model id and agent options, then swaps only the memory snapshot fed to the prompt.

Insights
  • A correction that never reaches the prompt is theater — the reply arm must consume the new snapshot.
  • Provenance edges come from recorded ids, not fuzzy wording similarity.
  • Fixture mode proves the pipeline; live Cursor runs are the model score.
  • Substring rubrics are honest about their limits — and force reproducible claims.
Limitations & future work
  • Synthetic people and planted stale beliefs — not a field study of production chat logs.
  • Causal claim is scoped: replies differ because the memory list differed, under fixed agent settings.
  • Rubric is lexical; paraphrases can fail adherence or false-flag leakage.
  • Next: user study on trust repair; stronger paraphrase scoring; rate limits before wider deploy.
Takeaway

Make the memory loop visible enough to audit — and measurable enough to fail.
